- `code/solve_python.py` — исходные данные, CPM, резервы, обходные пути,
  обе модели PERT, линейная оптимизация SciPy/HiGHS и проверки.
- `code/model.mod`, `code/variant11.dat`, `code/solve.run` — автономная
  реализация оптимизационной части в AMPL.
- `code/solve_ampl.py` — запуск AMPL через amplpy, сравнение двух задач
  и кривой затрат для 36 сроков с результатами Python.
- `code/make_report.py` — генератор PDF в стиле предоставленного образца.
- `results/` — рассчитанные значения и журналы фактических запусков.
- `LR5_variant11_report.pdf` — итоговый отчёт.

## Установка

Нужен Python 3.10 или новее. Создайте виртуальное окружение и активируйте его:

```sh
python -m venv .venv
# macOS/Linux:
source .venv/bin/activate
# Windows PowerShell:
# .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m amplpy.modules install highs
```

AMPL и HiGHS устанавливаются отдельно последней командой. Модель мала
(21 переменная, включая фиксированное сокращение фиктивной работы) и
успешно выполнена с входящей в комплект демонстрационной лицензией AMPL.
В другой среде условия доступной лицензии могут отличаться.
Официальная инструкция: https://amplpy.ampl.com/en/stable/getting-started.html

## Запуск из корневой папки архива

```sh
python code/solve_python.py
python code/solve_ampl.py
python code/make_report.py
```

Первый скрипт создаёт `results/python_results.json`, второй требует этот файл
и создаёт `results/ampl_results.json` и `results/ampl_log.txt`.
Для формирования отчёта нужны оба JSON и шрифты Arial или DejaVu Sans.
На macOS, Linux и Windows стандартные папки этих шрифтов проверяются
автоматически; альтернативную папку можно указать через `LAB_FONT_DIR`.
Шрифты не включены в архив.

Для самостоятельного запуска AMPL без Python API:

```sh
cd code
ampl solve.run
```

Если AMPL установлен через модули Python, вместо последней строки:

```sh
python -m amplpy.modules run ampl solve.run
```

## Основные результаты

- Исходный критический путь: b1, b3, b6, b8, b10; 49 дней.
- Минимальная стоимость: 389 ден. ед. при сроке 30 дней.
- Минимально возможный срок: 14 дней; наименьшая стоимость для него 468.
- При обязательном сроке не более 28 дней: 392 ден. ед.
- PERT без промежуточного округления: средние критические сроки 30 и 33,8.
- По правилу выбора максимальной дисперсии из пособия вероятности
  выбранного пути к 28-му дню: 0,243483 и 0,021905.
- В двухпараметрической модели второй критический путь имеет вероятность
  0,012192. В рамках нормальной аппроксимации это верхняя граница вероятности
  завершения всей сети к 28-му дню; 0,021905 не является совместной вероятностью.
- Оценки сроков надёжности 0,90: 33,687168 и 37,487168 дня (34 и 38 полных дней).

## Методические соглашения

Длительности непрерывны. Промежуточные средние не округляются; для сравнения
рассчитан и вариант с округлением каждой средней до целых дней, как в пособии.
Дисперсии в обеих моделях равны ((tmax-tmin)/6)^2.
Независимые резервы не обрезаются нулём — используется определение пособия.
Некритические дуги — обходные пути между событиями критического пути.
Отдельная фиктивная работа f=(5,6) сохраняет исходные зависимости.

Стоимость C = 10*T + сумма s[k]*x[k], где x — сокращения работ.
Срок 28 дней относится к вероятностной части задания; отдельно исследован
и как обязательное ограничение оптимизации. Базовая постоянная стоимость
работ в условии не задана, поэтому к C не прибавляется.

В `python_results.json` пути записаны индексами строк DATA с нуля,
события — номерами 0..8. Векторы длительностей содержат 12 элементов:
b1..b11 и нулевую фиктивную работу. В Python вектор сокращений содержит
только 11 реальных работ, в AMPL — также фиктивную работу (последний ноль).

Проверки сравнивают оптимальные значения, а не все сроки некритических событий:
например, в оптимуме стоимости AMPL может выбрать y[2]=14, тогда как ранний
срок события 2 равен 12. Оба расписания допустимы.
